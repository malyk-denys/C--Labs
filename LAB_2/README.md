# Лабораторна робота №2: синхронізація потоків C++

У папці містяться 7 окремих програм за пунктами 1.2.1–1.2.7, звіт із лістингами за пунктом 1.2.8, вихідна методичка, приклади вводу, автоматичні перевірки та налаштування VS Code. Стандарт: **C++17**.

## Швидкий запуск у VS Code

1. Відкрийте **File → Open Folder → LAB_2**, або файл `LAB_2.code-workspace`. Потрібно відкрити саме цю папку, щоб VS Code підхопив її `.vscode`.
2. Для підказок та F5 установіть рекомендоване розширення **C/C++ (Microsoft)**, якщо його ще немає. Збірка й запуск через термінал не залежать від розширення.
3. Відкрийте **Terminal → New Terminal** (PowerShell).
4. Зберіть усі програми:

```powershell
.\build.cmd
```

5. Запустіть потрібне завдання, наприклад перше:

```powershell
.\run.cmd -Task 1
```

Введіть `-5 0 1 2 3 4 17 25 97 q` і натисніть Enter. Очікуваний результат: `Прості числа: 2 3 17 97`.

Альтернатива: **Ctrl+Shift+P → Tasks: Run Task → Run task**, потім виберіть номер. **Ctrl+Shift+B** збирає всі програми. Для налагодження відкрийте `src/task_N.cpp`, установіть точку зупинки та натисніть **F5**. Ввід відбувається в окремій консолі, яку відкриває конфігурація налагодження. Через оптимізацію `-O2` покрокове виконання може пропускати деякі рядки; за потреби замініть `-O2` на `-Og` у `build.ps1` і перебудуйте.

## Команди для кожного завдання

| Команда | Що демонструє | Приклад вводу |
|---|---|---|
| `.\run.cmd -Task 1` | Прапорець, `unique_lock`, сон 100 мс | `2 3 4 17 q` |
| `.\run.cmd -Task 2` | Три потоки, два `notify_all`, предикат `i == 1` | Не потрібен |
| `.\run.cmd -Task 3` | Одне повідомлення через `notify_one` | Не потрібен |
| `.\run.cmd -Task 4` | Черга і `condition_variable` | `2 3 4 17 q` |
| `.\run.cmd -Task 5` | `deferred` проти `async` | `1000000`, потім `1`, потім `3` |
| `.\run.cmd -Task 6` | Два деки, `packaged_task`, фоновий виконавець | `1 2 10 100 q` |
| `.\run.cmd -Task 7` | `promise/future`, два від’єднані потоки | `10` |

`q` / `Q` і кінець потоку вводу завершують введення чисел. Номери простих чисел починаються з 1. У завданнях 5–6 допустимі номери до 10 000 000, у завданні 7 — до 1 000 000, оскільки додатково обчислюється номер `10*n`. Обмеження захищають від непомірних витрат пам'яті. У завданнях 1 і 4 приймаються знакові 64-бітові цілі числа; дуже великі прості числа можуть перевірятися довго через перебір дільників.

## Автоматична перевірка та вимірювання

```powershell
.\verify.cmd
.\run.cmd -Task 5 -Benchmark
```

Перша команда повторно збирає код, перевіряє прості числа, помилковий/порожній ввід, EOF, обидва режими `async`, чергу із 50 завдань, двосекундне очікування та по 10 запусків завдань 2 і 3. Журнал записується в `docs/verification.txt`. Кожен процес має тайм-аут 30 секунд: зависання означатиме помилку перевірки.

Benchmark обчислює мільйонне просте число в обох режимах та імітує 500 мс іншої роботи. `wait_ms` — тривалість лише `future.get()`, `total_ms` — від запуску `async` до отримання результату. 500 мс входять у загальний час, але не є часом обчислення простого числа. Результат в обох режимах: **15485863**. Час залежить від ПК та його навантаження; конкретну перевагу в мілісекундах тести не вимагають.

Запуск готових програм без повторної збірки:

```powershell
.\run.cmd -Task 6 -NoBuild
Get-Content .\samples\numbers.txt | .\build\task_1.exe
Get-Content .\samples\indices.txt | .\build\task_6.exe
```

## Важливі пояснення до реалізації

**Завдання 3.** Після одного `notify_one()` два потоки можуть залишитися в очікуванні. Програма чекає одного робочого повідомлення, після чого виставляє окремий прапорець завершення і викликає службовий `notify_all()`. Решта потоків виходить без робочих повідомлень. `delivered` захищає від повторної обробки при спонтанному пробудженні. Усі ці дії виконуються під м'ютексом. Це доповнення для коректного завершення, а не три робочі пробудження.

**Завдання 4.** Щоб зберегти обробку після завершення вводу й предикат `!data_queue.empty()`, виробник публікує пакет даних із маркером кінця `std::nullopt`. Навіть порожній ввід містить цей маркер: споживач не зависає. Прапорця готовності та опитування з `sleep_for` немає.

**Від’єднані потоки.** У завданнях 1, 4, 6, 7 використано `detach()`. Головний потік очікує спеціальні `future<void>`, які стають готовими через `set_value_at_thread_exit()`. Це гарантує завершення потоків до виходу з `main`.

**Фраза «вивести на стандартний пристрій вводу» в методичці** інтерпретована як друк у стандартний потік виводу (`std::cout`).

## Залежності

На цьому ПК знайдено **GCC 15.2.0**, `C:\Users\malyk\gcc\bin\g++.exe`, та GDB поруч із ним. Скрипт шукає `g++` у `PATH`, потім у `%USERPROFILE%\gcc\bin`; також підтримується змінна `CXX` із повним шляхом до компілятора. Налаштування F5 та IntelliSense використовують `%USERPROFILE%\gcc\bin` — на іншому ПК змініть відповідні шляхи у `.vscode`.

Збірка статична (`-static`), сторонні бібліотеки не потрібні. Компілятор і VS Code до папки не копіюються. Для роботи скриптів достатньо Windows PowerShell 5.1; `.cmd`-обгортки задають `ExecutionPolicy Bypass` лише для запущеного процесу, не змінюючи системну політику.

Перед поданням заповніть особисті реквізити титульної сторінки звіту та перечитайте пояснення й декларацію використання ШІ. Дані про заклад, групу та викладача не вигадані.
